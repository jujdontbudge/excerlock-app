# 0030: Recoverable and cancellable running linked test

- Status: Amends [0029](0029-guided-linked-test-flow.md). The guided two-app flow, the lab isolation boundaries, and the finish-only-by-return-link rule stay in force; the “Trace Lab must never persist the nonce” alternative and the “a running trace stays running if the hand-off failed” consequence below are superseded. Also records the finalized-marker authority, the recorder's neutral reminder card, the archive-protection and neutral active-recording refusals, the single-read lifecycle reconciliation, and whole-word launch-evidence matching that the later correction rounds added to the same flow.

## Decision

A running Trace Lab test is recoverable and escapable without ever looking finished.

Trace Lab keeps a lab-local copy of the active handshake (session UUID, one-time nonce, protocol version) under one namespaced key in its own sandbox, written best-effort when the test starts and cleared when the test is saved, cancelled, expired, or found inactive. That copy is not evidence: only Walking Recorder's own return link can move a test to **Test finished — save it**. Its only purpose is to reopen the exact `excerlock-walkingrecorder://linked-session` link after a Trace Lab relaunch, so a person can continue the same test instead of opening a bare recorder. The copy never enters an export and is never uploaded; Walking Recorder's protected recovery file remains the recorder-side copy.

Beside the primary hand-off, a running test exposes one quiet, confirmed **Cancel test** action (subordinate text action, destructive confirmation). Cancelling writes a durable `abandoned-v1.json` record (`reason: cancelled`) instead of a finalized marker as the one authoritative abandonment transition, under the existing session lock and before anything else changes; then it stops native tracing, removes the isolated walking rule, deletes the unfinished trace payload, and clears the active descriptor. Expired cleanup writes the same record with `reason: expired`. `finalizedSessions()` never lists an abandoned session and `exportFinalizedSession()` refuses it; the tiny record stays in the lab App Group until the existing retention pruning removes it, so a void test keeps no measurement data but cannot masquerade as completed. A process that dies between those steps leaves the marker behind, and every later writer call finishes the same abandonment idempotently before it can observe a live session: a cancelled test can never be resumed, appended to, finalized, listed, or exported again, while a clean session can still start afterwards.

The two durable markers are symmetric in authority, and neither can be undone by the other. `finalized-v1.json` is written first, under the same lock, as the authoritative start of finalization; if the process dies before the descriptor is dropped, the next writer call finishes the same save instead of observing a live session: it keeps every recorded byte, appends the missing `trace_stop` event at most once (never a second one when the crash was later), drops the stale descriptor, and then behaves exactly like a completed save. A finalized session is therefore never reported active, never resumed or appended to, never cancellable, and never deleted by a cancel; `cancelActiveSession` on it finishes the pending save and refuses with `inactive`, while the trace stays listable, re-exportable, and explicitly deletable. A retried save of that session returns the same export instead of failing or writing a duplicate stop event.

## Context

ADR 0029 rejected “let Trace Lab persist the nonce itself” because the recorder was meant to be the single owner of recovery. That model holds only while the recorder actually received the link. If the hand-off never reached Walking Recorder (the open failed, the app was reinstalled, or it was killed before processing), Trace Lab was left holding a running trace with no way to finish it and no exit except the two-hour limit, and the linked-recorder review required an honest bounded escape with enough retained handshake state to reopen the intended recorder flow where safe. Confusing the retained copy with finish evidence would be worse than the escape it enables, so the copy stays inert for phase decisions.

## Consequences

- An interrupted test now has three truthful outcomes: continue it through the recovered recorder link, finish it through the recorder's return link, or cancel it and start clean. Cancelling saves and exports nothing and leaves only the abandonment record.
- The recorder-side reminder that returns to Trace Lab is not a "saved" record: Trace Lab may have saved the trace or cancelled the test, and it never reports which, so the recorder's **Linked test recorded here** card states exactly that and offers **Open Trace Lab** to save or check. The card is neutral by construction, not a "not saved yet" claim, because a cancellation in Trace Lab makes that claim false; it removes its non-exported one-time link only through one neutral **Remove this reminder** action with an inline confirmation that it must be used only after Trace Lab no longer needs the test. That removal never touches the recording archive.
- A refused cancel lands on the truthful step, not on an error: Trace Lab re-reads its own status and saved list after a failed cancel, so a save that was already finalized shows the saved-test card with the existing "already saved" note, and only a genuinely still-active trace keeps the "may still be running" recovery message.
- Every pending linked recovery protects its own archived recording, not only the reminder the card currently surfaces: deleting any saved archive whose own protected one-time link still waits for Trace Lab is refused with a notice naming that specific test, and the archive becomes deletable only after that test's own reminder is explicitly cleared. The archive store performs the same refusal itself, so deleting through the repository cannot bypass the controller guard.
- A linked delivery that arrives while this phone is already recording gets one neutral refusal that is true for an ordinary labeled session and for a different linked test alike: it says a recording is already running on this phone and to finish and save it before starting the linked test, instead of claiming the running recording is a linked test.
- While a test runs, Trace Lab's recovery help names both truthful interruption cases: finish the test in Walking Recorder while it is still recording, or tap **Open Trace Lab** on its neutral **Linked test recorded here** reminder card once it already finished, and either path returns to Trace Lab to save the trace.
- One status read serves both the screen payload and the lifecycle-observer reconciliation: the host reads the writer exactly once per status call and passes that same active value into the reconciliation, so a poll never repeats the lock/prune read and the payload can never disagree with the decision.
- The one-time nonce exists in two lab-only sandboxes during a test: Trace Lab's namespaced recovery copy and Walking Recorder's protected recovery file. Both stay on the device, out of every export, and are cleared with their session; no production ExcerLock code imports the research store module.
- The trace contract gains `abandoned-v1.json`; finalized and abandoned sessions are distinguished by distinct markers, and only finalized markers are listable or exportable. Each marker is authoritative over the descriptor that follows it, so an interruption between a marker and its cleanup recovers to that same outcome instead of reopening the session.
- The launch-evidence gate matches whole Trace-Lab-specific marker combinations on whole normalized words, so generic recorder copy (for example a Walking Recorder notice containing “Recording on this phone”) can never satisfy a Trace Lab launch phase. Development-server evidence must be a distinctive multi-word phrase: a word that merely contains “metro” is unresolved, so the proof retries the observation instead of ending with a false dev-server diagnosis, and only a real dev-client prompt fails immediately.
