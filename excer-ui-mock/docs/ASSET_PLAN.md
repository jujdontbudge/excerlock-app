# ExcerLock UI mock — asset audit and production plan

> **Executed outcome — 2026-08-07.** The final standalone foundry contains 79
> runtime finals and 77 neighboring opaque/source edit targets: 2 branding
> squares, 8 heroes, 26 glyphs, 22 badges, and the complete 21-banner library.
> The plan below proposed reusing accepted Manage/Settings tab masters; the
> production pass instead generated fresh GPT Image 2 Manage and Settings
> glyphs, so the actual split is **37 reused finals / 42 new finals**. All
> source/final paths, exact prompts, hashes, corrections, and acceptance gates
> are authoritative in the nearest `assets/**/FOUNDRY.md` manifests.

## Decision summary

This plan applies the pasted mission, `design/STYLE.md`, the full PRD, the
Pillow audit/synthesis, and the approved ExcerLock anchors to the standalone
`excer-ui-mock/` app. It is planning only: no asset or app file has been
created or changed.

The strict lineage rule is:

- A runtime PNG is allowed only when its visual subject was produced by GPT
  Image 2 through Codex `image_gen`.
- Deterministic normalization, chroma-key removal, resizing, cropping, and the
  Family-E square composition are allowed. They are the required STYLE.md
  post-processing steps, not alternate image generators.
- A prior image may be used as a style reference when the mission explicitly
  names it as ground truth, but a final generated by Nano Banana, Seedream, or
  another renderer may not be copied into `excer-ui-mock/`.
- A manifest entry is required before any final is imported by app code.

The resulting inventory is:

| Class | Existing finals that can be reused | New GPT Image 2 finals | Runtime total |
|---|---:|---:|---:|
| Branding (Family E) | 2 | 0 | 2 |
| Clay hero/cutout (Family A) | 2 | 6 | 8 |
| White glyph (Family B) | 11 | 15 | 26 |
| Achievement badge (Family A) | 22 | 0 | 22 |
| Painted condition banner (Family C) | 0 | 21 | 21 |
| **Total** | **37** | **42** | **79** |

The 21 banners deserve an explicit distinction:

- **Absolute tappable-flow minimum:** six fresh banners, one default per
  family: `gym-weights-floor`, `walk-city-sidewalk`, `run-road-dawn`,
  `cycle-open-road`, `swim-pool-lanes`, `general-abstract-energy`.
- **Honest showcase minimum:** seven; add `walk-park-path` so the Home STATE
  card and steps RATE card do not repeat the same artwork.
- **Full PRD/foundry requirement:** all 21. The banner picker is itself a
  required screen, the PRD promises a curated 4/3/3/3/3/5 library, and saved
  gyms cycle through four distinct gym banners. A six- or seven-image picker
  can unblock route implementation, but it is not a complete ExcerLock asset
  foundry. **Recommendation: generate all 21 before visual acceptance of the
  complete app**, in two batches (the seven showcase assets first, the other
  fourteen immediately afterward).

Full-screen mockups are design references, never runtime image layers. Charts,
meters, heat-map cells, live rings, scrims, gradients, toggles, radio dots,
sheet handles, and share-card layout are real UI. They do not need PNGs.

## Pipeline and validation commands

These are execution instructions for the later asset-production pass. Run from
`/Users/johansardar/ExcerLock`. They are not executed by this planning task.

### New Family A/B cutout

Use a unique path; never overwrite an accepted target. `asset_slug` must be an
explicit basename from the tables above.

```bash
asset_slug=permission-screen-time
opaque_path="excer-ui-mock/assets/heroes/${asset_slug}-opaque.png"
normalized_path="excer-ui-mock/assets/heroes/${asset_slug}-1024.png"
final_path="excer-ui-mock/assets/heroes/${asset_slug}.png"

sips --resampleHeightWidth 1024 1024 "$opaque_path" --out "$normalized_path"
python3 prototype/scripts/remove_chroma_key.py \
  "$normalized_path" "$final_path" --edge-contract 1 --despill
python3 prototype/scripts/validate_icons.py "$final_path"
```

Use the same commands with `assets/glyphs/` for Family B. Required command
result: `mode=RGBA`, `size=[1024,1024]`, all four corner alpha values zero,
`residual_chroma_pixels=0`, sensible non-transparent coverage and bounds.

Then inspect the actual final on the app gradient at every intended point size:

- Glyphs: 12, 18, 24, and 30 pt as applicable.
- Clay heroes: intended table size plus a 96 pt stress check.
- Reject any magenta fringe/box, missing thin part, ambiguous silhouette,
  unintended dark hole, gloss, detached piece, or baked shadow.

Corrections must use `precise-object-edit` on the existing opaque output and
name exactly one defect. Two failed corrections on one asset means stop and ask
Johan rather than prompt-drifting.

### Family C banner crop and checks

Do not use the magenta pipeline. Generate a full-bleed landscape source, keep
it as `<name>-source.png`, then center-crop and downsample once to the anchor's
runtime size. `ffmpeg -n` refuses to overwrite an existing accepted final.

```bash
banner_slug=walk-city-sidewalk
source_path="excer-ui-mock/assets/banners/${banner_slug}-source.png"
final_path="excer-ui-mock/assets/banners/${banner_slug}.png"

ffmpeg -n -i "$source_path" \
  -vf "crop=w='if(gt(a,1536/696),ih*1536/696,iw)':h='if(gt(a,1536/696),ih,iw*696/1536)',scale=1536:696:flags=lanczos,format=rgb24" \
  -frames:v 1 "$final_path"

test "$(ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,pix_fmt \
  -of csv=p=0:s=x "$final_path")" = "1536x696xrgb24"
```

OCR can catch accidental generated lettering, but it is only a heuristic:

```bash
test -z "$(tesseract "$final_path" stdout --psm 11 2>/dev/null | tr -d '[:space:]')"
```

The mandatory human banner gates are:

1. visual family matches the gym-card anchor;
2. no readable text, UI, logo, watermark, or fake signage;
3. no visible face; a permitted figure is distant/from behind/full silhouette;
4. center crop did not cut the semantic subject;
5. lower third remains calm under the real dark scrim;
6. white title, subtitle, status chip, and CTA all pass contrast at the real
   361×163 pt-equivalent card size;
7. no baked rounded corners—the UI owns clipping.

## Manifest layout and required fields

Create one manifest per asset directory:

- `excer-ui-mock/assets/FOUNDRY.md` — branding.
- `excer-ui-mock/assets/heroes/FOUNDRY.md` — Family A hero/cutouts.
- `excer-ui-mock/assets/glyphs/FOUNDRY.md` — Family B.
- `excer-ui-mock/assets/badges/FOUNDRY.md` — reused badges.
- `excer-ui-mock/assets/banners/FOUNDRY.md` — Family C.

Every accepted **and rejected** attempt needs an entry with these fields:

| Field | Required content |
|---|---|
| `asset_id` | Stable basename, e.g. `permission-screen-time` or `walk-city-sidewalk`. |
| `status` | `ACCEPTED`, `REJECTED`, or `SUPERSEDED`; app imports only accepted. |
| `family` | `A`, `B`, `C`, or `E`. |
| `runtime_final` | Exact project-relative destination. |
| `opaque_or_source` | Untouched `image_gen` output; `*-opaque.png` for A/B, `*-source.png` for C. |
| `generator` / `model` | Exactly `Codex built-in image_gen` / `GPT Image 2`; for copies, `byte-for-byte reuse of accepted GPT Image 2 asset`. |
| `use_case` | `new-asset-with-style-reference`, `precise-object-edit`, `reuse`, or `Family-E deterministic composition`. |
| `template` | `Family A canonical`, `Family B Template B2`, `Family C GPT override`, or `Family E`. |
| `verbatim_prompt` | Entire actual prompt, after slot substitution; no summary-only prompt. For reuse, include/inherit the original verbatim prompt and link the source manifest. |
| `reference_images` | Exact paths and the role of each reference. |
| `generated_output` | Original image_gen output path or generation identifier. |
| `postprocess` | Exact `sips`, keying, crop, resize, or composition commands. |
| `dimensions_mode` | Source and final width/height plus RGB/RGBA. |
| `validation` | Corners, residual chroma, coverage/bounds for A/B; square gates for E; dimension/OCR/face/scrim/style checks for C. |
| `display_checks` | Actual point sizes and background/card contexts inspected. |
| `screen_consumers` | Named routes/surfaces using the asset. |
| `sha256` | Final checksum; copies also record source and destination checksums. |
| `attempt` / `supersedes` | Attempt number and the prior target when a precise edit is made. |
| `rejection_reason` | Concrete defect and failed gate; mandatory for every rejected output. |
| `reviewer_date` | Who accepted it and when. |

For reused assets, the standalone manifest must not merely say “see old
foundry.” It should record the old manifest path, original prompt/template,
validation result, exact source/destination, and matching SHA-256 so the new
project remains auditable on its own.

## Recommended production order

1. Copy and revalidate the 36 byte-for-byte cleared finals (branding, lock
   pieces, ten canonical prototype glyphs, and 22 badges) plus their available
   opaque edit targets.
2. Re-key the retained house opaque output as the Home glyph, bringing the
   cleared/reused runtime total to **37**. Generate Manage and Settings fresh.
3. Generate the six Family-A cutouts; approve each before moving to the next
   semantic family.
4. Generate the thirteen activity/section Family-B glyphs in one style-locked
   batch; with fresh Manage and Settings, verify all 15 additions and all 26
   reused/new glyphs together at real sizes.
5. Generate the seven showcase banners: `gym-weights-floor`,
   `walk-city-sidewalk`, `walk-park-path`, `run-road-dawn`, `cycle-open-road`,
   `swim-pool-lanes`, and `general-abstract-energy`. This unblocks every
   required tappable flow and a credible initial banner-picker grid.
6. Generate the fourteen completion banners and require 21/21 before calling
   the UI/foundry complete.
7. Only after manifests are complete should app code import the finals and
   visual screenshot comparison begin.

This order keeps the looks-only prototype unblocked while preserving the final
standard: the delivered app has the full PRD banner library, every PNG has
GPT Image 2 lineage, and no runtime surface depends on the old `app/` or
`prototype/` trees.
