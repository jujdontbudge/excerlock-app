# Owner iPhone attribution evidence

This is a physical-device evidence driver explicitly requested for B1–B10, separate from the app and the simulator proof suite. It never resets, deletes or uninstalls ExcerLock. It uses the production bundle ID and real adapters, not demo scenarios. `Driver.swift` is compiled into a local XCUITest runner, never the shipping app. Existing development identities/profiles must already work; preparation does not register apps/devices, update portal resources or upload a binary.

Run `./tools/ad-device-proof/prepare.sh` from this worktree. It stages the Xcode project and all build output under gitignored `.excer/`; logs and device evidence go to `~/device-test/`. The Debug application needs a separate Metro instance on free port 8094, serving this worktree's keyed preview environment on the LAN, with `EXPO_PUBLIC_API_URL=https://api.excerlock.com/testflight` explicitly overriding local defaults. Never use another checkout's Metro or the lead simulator. Do not print build logs containing credentials; keep evidence private and redact any material before sharing.

Use `python3 tools/ad-device-proof/wait.py --hours 4` to poll the exact paired iPhone every 60 seconds. The watcher consumes/deletes `~/device-test/answer.txt`, saves its contents privately, updates `STATUS.txt`, records UTC lock evidence and exits on unlock. If the phone locks mid-run, resume with `--until <original ISO UTC deadline>` to preserve the original four-hour limit. The watcher reads only the private sandbox credential file’s readiness; it never invokes Keychain access from SSH. A missing lock-state result never counts as unlocked.

Before installation, inspect `com.johansardar.excerlock` with `devicectl device info apps --include-all-apps` or the read-only usbmux app query. The 2026-10-18 baseline is App Store 1.0.1 (21), existing container, 2,686,976 bytes of app data. Preserve that container. Never set `EXCER_EMPTY_INSTALL_CONFIRMED=1` for this baseline. The existing separate research bundle strips client configuration, including advertising and Adapty credentials (`app.config.ts`), and uses lab-local identity, so it cannot prove attribution or real StoreKit purchases for the registered apps. Replacing the production-bundle binary is authorized; data/container deletion is forbidden. Inspect the current screen and saved Conditions before running any flow that could change them.

`testSnapshot` activates the existing app and attaches UTC screenshots and the accessibility tree. `testRelaunch` records a normal cold reopen. Both can emit SDK activation events: start evidence capture first, record their UTC window and distinguish session activation from once-per-install events. They do not prove dashboard receipt.

For a genuinely empty install, `testOnboardingToPaywall` drives the real onboarding to the paywall and captures the checkpoint. It requires `EXCER_EMPTY_INSTALL_CONFIRMED=1`. It stops when a screen needs review rather than granting Screen Time/motion/location permissions. `EXCER_ATT_ANSWER=allow` selects Allow; otherwise the ATT prompt is denied. Never select actual Locked apps or enable a Condition on the owner's phone. The onboarding driver is prepared automation, not a verified flow until it has actually run.

`testTrialPurchase` and `testNoTrialPurchase` require all of `EXCER_SANDBOX_CONFIRMED=1`, `EXCER_NO_ACTIVE_ACCESS_CONFIRMED=1` and `EXCER_OWNER_DATA_SAFE=1`, based on observed evidence. The no-trial path also requires `EXCER_DISTINCT_ACQUISITION_ACCOUNT_CONFIRMED=1`: a counted trial deliberately suppresses a later Subscribe for that account. This driver does not switch the owner's identity or clear the acquisition ledger. Choose the actual monthly no-trial product and verify Apple's signed transaction price/currency afterwards; do not infer eligibility from the selected plan alone. The driver will never tap StoreKit confirmation without a visible “Environment: Sandbox” label. Authentication/side-button confirmation stops for the owner. Never use the `APPLE_SANDBOX_*` environment values: repo memory identifies those as the owner's real account. The dedicated tester is listed in `~/device-test/sandbox-testers.json`, with password available only through Keychain service `excer-sandbox-tester`. Never log a password or put it in runner arguments.

Run one selected method using `xcodebuild test-without-building -xctestrun <generated .xctestrun> -destination 'platform=iOS,id=00008110-000E5041260BA01E' -only-testing:AdDeviceProof/DeviceDriver/testSnapshot -resultBundlePath <new private path>`. Discover the generated xctestrun under `.excer/device-driver-build/Build/Products/`. To set guards, edit only that local xctestrun's `EnvironmentVariables` dictionary after reviewing prerequisites. Keep each flow within five minutes. Extract attachments using the installed `xcresulttool export attachments --help` flags. No StoreKit configuration file is attached: Xcode transactions intentionally do not generate acquisition events.

Capture the reviewed native SDK diagnostics with `pymobiledevice3 syslog live --udid 00008110-000E5041260BA01E --process-name ExcerLock | python3 tools/ad-device-proof/capture.py`. The collector discards all lines except the exact reviewed initialization/event diagnostic grammar; no arbitrary SDK request dump is retained. `events.ndjson` records the host's UTC observation time and each native invocation separately. It is not a receipt or proof of SDK automatic install events. Never turn on verbose TikTok logging. Whole-payload B10 requires a separately observed decrypted network capture; this collector cannot substitute for that evidence. IDFA must be read locally only after observing ATT authorization, then recorded in the private report; do not infer it from a vendor anonymous ID.

After the run, verify that no shields, schedules or Locked apps were created; undo only changes made by this run. Do not remove the owner's pre-existing Conditions or blocks. Record the final installed version and container. Never reinstall the App Store app just for cleanup. Record each B test as pass, fail or blocked, with separate owner-accepted policy notes. Dashboard checks are read-only; no configuration changes are authorized.
